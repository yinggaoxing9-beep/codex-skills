# 生产终端直接粘贴复杂采集脚本复盘

## 来源与范围

来源为用户在 2026-10-23 提供的生产操作复盘及本次交付要求纠正；已脱敏，去除人员、公司环境、节点地址、实际路径和内部图片认证链接。文档反映用户提供的记录，未在此次 Skill 更新中重查生产环境。

## 经过与已知结果

为统一节点 DNS 配置并评估 kubelet 变更影响，需要采集节点服务、Pod 健康及设备资源状态。AI 辅助生成包含批量查询、并发控制和预检逻辑的长脚本，随后在生产操作节点 root 会话中直接粘贴执行。用户提供的复盘记载，该方式增加了历史记录和审计追溯困难；检查后确认未造成业务影响。这是文档中的结论，不是本次更新独立验证的现场状态。

采集脚本与后续 kubelet 变更属于不同操作；不能把后续重启风险写成该次采集已经触发服务重启或故障。

## 关键纠正

- 核心是对生产终端粘贴复杂脚本的风险判断不足，不能只写内容核对或审计不便。
- “查询、只读”不是直接粘贴长脚本的依据；误粘贴、部分执行、高权限误操作以及批量查询负载均需评估。
- 文件交付必须落实审核验证；复制同样长的 heredoc 到生产终端、压成一行或拆成多次粘贴不是修正。
- 不将原因归咎为用户没有向 AI 提供足够详细的分步提示。助手应交付可审阅文件和简短入口，并明确验证边界。

## 预期后续行为

复杂脚本先文件化交付，执行前审核和检查最终字节，在获准环境验证并先限定范围灰度，终端只提供简短的校验与执行入口。保留版本和执行证据，业务影响按真实证据报告。

## 限制

不证明曾发生误执行、配置损坏、数据丢失或业务中断；不继承原环境状态、具体并发阈值、审批结论或执行授权。堡垒机控制是补充，不保证已部署或支持某种功能。
