# 最终入口发布验证

用于交付或修改 Ansible 部署入口、阶段包、安装器及其依赖物料。验证由助手在获准的本地/隔离环境先完成；仅有现场访问权限的检查才交由用户执行。

沿实际执行位置、Ansible/集合/解释器版本、命令、inventory、变量与包内路径核对最终交付物；版本不匹配且无法取得匹配运行时，明确缺口，不把另一版本的通过结果称为兼容通过。

- 对最终归档解压后的入口执行解析与范围预览，核验引用文件、权限与相对路径。写明 cwd；源码存在不代表包内存在，绝对路径可用不代表用户的相对入口可用。
- --syntax-check、--list-hosts、--list-tasks 分别检查语法和展开范围。对本次变更涉及的运行期 Jinja、shell 引号及动态 include，再用合成输入和无副作用 task 实际渲染/执行相关路径；不要用静态通过替代这些行为证据。
- 只需读取或静态分析时不触发部署；--check 也不能默认当作无副作用隔离。运行期验证须确认没有业务目标、delegate_to、命令任务或共享资源写入泄漏。
- 用最终版本包及一份完整更新说明交付，并列出必要依赖；原包加增量补丁是既定机制时，验证组合后的入口。每次修改重验受影响路径和摘要链，不堆出需要用户猜顺序的多个补丁。
- 已通过的采集/校验继续复用，补取缺失证据。报告区分静态解析、隔离运行、现场灰度与全量验收；用户报告跑通不等于助手独立验收全量。

这套发布验证不适用于普通只读查询或概念解释。批量阶段契约、等待与并发决策属于部署流程设计，本参考只负责证明交付入口确实消费了预期文件和参数。
