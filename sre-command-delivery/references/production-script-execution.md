# 生产脚本交付与执行

## 判断执行方式

先区分简单查询和复杂脚本。一个范围明确的短查询可直接交付；多阶段采集、循环、并发、嵌入 Shell/Python、状态检查或异常恢复逻辑应交付独立文件或物料包。没有“少于某行数就安全”的结论；减少换行、拆成几次粘贴或改成编码文本不能改变审核要求。

用户要求直接给命令时，先完成本地文件制作和可完成的验证，再交付文件下载或传输路径，以及目标环境的简短校验/执行入口。使用会话已确认的传输方式；没有传输入口时说明所缺条件，不退回生产终端粘贴完整脚本。

## 线上风险及边界

- 交互式终端可能在粘贴过程中执行已完整输入的命令；截断、换行异常、嵌套 heredoc 或混入提示符可能导致部分执行、错误解析或意外读取后续输入。不能保证终端一定逐行执行；具体行为取决于 shell、终端和粘贴模式。
- root 权限与 Kubernetes 凭据权限分别确认。操作系统 root 不自动代表集群管理员；高权限凭据会扩大错误操作的影响范围。所谓只读意图不保证脚本没有其他副作用。
- 查询同样占用资源。节点代理查询可能访问 kubelet，批量对象查询和原始 JSON 输出可能增加 API Server、网络、CPU、内存和磁盘负载。并发上限、请求超时、输出量和停止条件按环境确定，不照搬历史阈值。
- 终端历史和审计系统的保留方式需要单独核实；长文本可能增加记录量、占用历史容量，但不能无证据断言记录丢失。Pod 配置、环境变量、内部地址等采集结果可能敏感，控制采集字段和文件访问权限。
- 风险不等于已发生影响。复盘分别记录观察、可证明结论和缺口；不把未提供审批材料写成未经审批，不把没有业务异常证据写成已经证明绝无影响。

## 文件交付与验证

1. 在源文件中明确目标范围、权限、查询/变更边界、分阶段检查点、并发、超时、失败传播和逐对象结果。日志不含凭据；异常保留上下文，不用空结果掩盖失败。
2. 审阅所有实际执行的文件和嵌入逻辑，完成语法、解析及本次逻辑所需的隔离测试。修改生产状态时审核中间状态与恢复措施；纯采集也检查负载、落盘及敏感数据边界。
3. 最终文件固定版本，生成摘要，再按实际调用位置、相对路径和依赖检查最终入口。哈希只证明字节一致；语法检查只证明解析通过，两者均不能证明业务安全。
4. 现场先限定对象灰度，核对服务和资源状态后按已授权范围推广。没有匹配环境或权限时保留文件，说明未验证层级，不声称生产可用，也不反复请求已经取得的授权。
5. 用户终端只接收简短目标确认、文件摘要验证和执行入口。校验不通过停止，不自动重算摘要当作正确版本，也不通过管道将未审核下载内容交给 shell。
6. 记录原始文件版本与摘要、执行主体、目标、时间、结果及必要的备份位置；文件与日志关联。按需打包返回，敏感文件限制访问并按要求保留。

## kubelet 与设备插件变更

涉及 kubelet DNS 或运行时配置时，先梳理业务 Pod、基础服务、设备占用、调度约束及设备插件状态。重启后的验收包括节点与 Pod 就绪、业务容器身份及重启次数、设备 capacity/allocatable、DNS 与实际服务请求。只有证据表明需要时才重建设备插件，不因节点类型统一重启；验收失败时暂停相关后续变更，保留现场排查。此段不提供重启授权。

## 防护措施的定位

堡垒机提示、复核或拦截可以减少误操作机会，行数阈值只是辅助条件，不能覆盖所有短命令或文件执行风险。测试、审核、最小权限和授权分别承担不同职责，不能写成满足任一项即可执行。
