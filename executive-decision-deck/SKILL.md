# 管理决策演示

与 `Presentations` 组合使用。先明确要谁在何时做什么决定，再构建答案优先的故事线：决策摘要 → 背景变化 → 选择标准 → 可选方案 → 证据与取舍 → 建议 → 风险/敏感性 → 执行与所需授权。

沿用 `mode: live | read | hybrid`，按 [使用模式](../presentation-studio/references/authoring-modes.md) 决定密度、来源/条件位置与验收：live 服务现场决策过程，read 让缺席者独立判断，hybrid 明确一条主路径及可查补充层。

- 首页后的第一张内容页应让缺席者知道建议、价值、代价和请求。
- 每个选项使用同一评价标准；沉没成本、未来投入和不可逆性分开。
- 定量主张保留基准、单位、期间和来源；情景或预测不得伪装成实际数据。
- 沿用 [证据与页面契约](../presentation-studio/references/contracts.md)，区分事实、估计、推断、建议并回链依据；把决定性证据的解释连接到行动及成立/停止条件。可跨页完成链路，不把每页强制排成四格。
- 正文只保留影响决策的证据，方法细节和备选分析放附录。
- 行动页明确责任、时间、依赖和决策门，不用空泛口号代替执行计划。
- 演讲备注准备最可能的反对意见及回答依据。

有参考作品先读 [参考转译](../presentation-studio/references/reference-translation.md)；需要结论总览、指标、阶段路线或比较矩阵时选读 [完整页例](../presentation-studio/references/page-examples.md)。定量图形按 [真实性指南](../presentation-studio/references/chart-integrity.md) 复算映射，不能用漂亮图形代替证据。

基础渲染验证由 `Presentations` 完成；用户要求独立审阅/修复，或涉及高风险决策、关键定量结论及复杂改版时加载 `deck-review`。无论是否加载，都确认请求明确、建议有依据、选项口径一致、决定性风险及授权条件可见；会改变批准结果的遗漏应阻止交付。
