# 项目适配契约

适用于把研究流程接到已有数据、因子注册表和评估器。先读取当前项目规则及真实CLI帮助；优先复用已有数据契约、哈希与生命周期，不复制一套相似实现。

## 可替换的研究组件

| 组件 | 最小输入与输出契约 | 核验重点 |
| --- | --- | --- |
| 数据适配器 | 来源与PIT语义、code/date、报价/事件字段、统一日历、覆盖清单、指纹 | 复权锚、单位、历史成分、缺行、版本可追溯 |
| 猜想目录 | ID/版本、机制、公式、可得时点、所需数据、能力状态、限制 | 原猜想与代理规则的差异明确；不按结果静默改定义 |
| 信号计算器 | 仅当时与过去输入，输出可用性与信号 | 未知和false分开；截断/未来扰动测试；跨股票隔离 |
| 标签与事件器 | 固定日历、标签成熟、重复事件策略、所有事件及不可评分理由 | 保留执行失败；不根据未来成败选事件 |
| 评估器 | 预声明对照、阶段、终点、依赖处理及试验家族 | 结果含样本量/效应/区间/校正/覆盖；不强求所有候选可评 |
| 执行验证器 | 明确订单策略、撮合约束、成本和连续资金路径 | 条件事件收益与账户收益有不同名称和门禁 |
| 注册表与报告 | 不可变定义、追加状态事件、实验清单、可重跑命令 | 未通过准入不写生产活跃清单；研究报告不得触发通知 |

实现新适配器时，仅在输入/输出契约和真实能力已核验后接入。同一种指标名称未必同口径；若原项目只支持事件研究，先明确该能力边界，不能从成功退出码推断策略收益有效。

## 外部方法和可扩展研究框架

论文、文章、开源框架先登记来源、版本和实际读到的主张，再提取可检验机制。把作者观点、直接证据和自己的工程推演分开；不能将未读内容归因给来源。新方法可增加特征、标签、对照或评估组件，但每次改动形成新实验版本，并核对其数据、计算量和权限要求。

复用项目适配记录时，核验目录、CLI参数、数据截至日和函数签名；历史案例只帮助定位。具体项目说明放技能的example目录，不将本机路径、特定股票、固定阈值或单轮结果写成通用要求。

## 研究谱系与经验提升

为每轮记录experiment_id、parent_experiment_id、猜想来源、定义/数据/代码版本、已观察的结果、允许修改及放弃条件。保留原始工具与运行记录(trace)，再组织为从问题到决定的完整过程(trajectory)。不要只摘取最终盈利片段作为经验；比较独立轨迹中的失败、反证与适用边界，再判断规则能否复用。

当研究助手有现代知识时，历史回放与真正受限于历史时点的研究环境分别标注。历史行情截断、公告PIT和数据泄漏测试解决可观测代码路径的问题，不能清除模型已有知识或研究者已知的结果。需要更强结论时采用未见资产/时期、独立复现或前瞻影子研究，并说明仍存的污染渠道。
