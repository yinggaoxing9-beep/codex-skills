# 构建与验收

## 数值与几何

选定数据源后生成静态图形；不要让表格、标签、图形拥有互不相关的手填数值。若手工维护，必须计算核对。静态 SVG 适合离线、无 JS 与打印；图中有语义标题、描述，旁边提供完整数值表。

- 线性条形：`width = plot_width * (value - baseline) / (max - baseline)`；比较大小通常 baseline=0。同图必须统一单位、基线和比例；负值需围绕真实零线编码，不能套仅支持正值的 starter。
- 1× 和 50×：在 0–50、500px 的同一坐标系中分别是 10px、500px；等长条配不同数字仍会误导。若跨度大到难读，选正数对数轴、分图或数值表，并明确尺度，不能给短条设最小宽度伪造比例。
- 对数轴：`x = x0 + W * (log(v)-log(min))/(log(max)-log(min))`，v/min/max 都必须 >0；零和负数另作说明，不允许画 0 刻度或把 0 当 1。
- 缺中间值：可展示已知起点/终点及“中间贡献未知”，不能用均分或装饰性的下降台阶冒充瀑布归因。
- 只有作者测算或情景值时写“估计/预测/示意”及假设；实测需测试条件；图例使用文字与虚线等非颜色编码。

## starter 审计契约（可选）

仅在采用 `data-chart="bars"` 时启用几何审计。图表的 `data-table` 指向真实数值表；每行 `data-key` 唯一，数值单元格 `data-value` 与其可见数字一致。SVG 标注 `data-scale="linear|log"`、`data-min/max`、`data-plot-x/width`；每条 `rect[data-bar]` 以 `data-key` 对应表行，最终 x/width 写入源码；每个 `text[data-label]` 显示同一个数值。`text[data-tick]` 的 x 也参与计算核对。无 JS 时这些值仍存在。

脚本只支持水平正值条形图，其他图型/负值须另做数值核验；不能靠给错误图加标签绕过几何检查。不采用契约的 SVG、CSS 图、canvas 等会提示尚未审计，仍须人工或专用工具核对。脚本不会判断来源真伪、CSS 级联最终结果、图形遮挡、颜色对比、预测方法或文字结论。

## 屏幕与无障碍

正文通常 16–18px 起，按目标屏幕调整；行距约 1.65–1.9，长段限制行长。允许放大至 200%，不要用固定高度裁正文。窄屏检查标题断行、图中文字大小、横向溢出；复杂图可提供可聚焦的横向滚动容器和文本解释。

目录使用真实 `href="#id"`，章节留 `scroll-margin` 避免 sticky 导航遮住标题。配置跳转正文链接、可见 `:focus-visible`，所有控件可键盘操作；状态不仅靠颜色。机制流程在 DOM 中保留顺序或文字等价物。带横向滚动的宽表具有说明、`tabindex="0"` 和可访问名称，表头用 `scope`；移动端不要将普通单元格随意伪装为缺少标题关系的卡片。

核心内容无需 JS：初始 DOM 已有全部章节、最终数字、来源；不要 `display:none` 隐藏整章后等待脚本切换。可选次要细节用 `details open`，在 JS 已启用后允许用户收起。脚本只做增强；URL hash 仍能直达章节。`prefers-reduced-motion: reduce` 关闭平滑滚动、过渡与循环动画；未动画状态仍完整。

## 打印与资源

打印 CSS 至少覆盖：所有章节、折叠内容、溢出容器、固定高度、sticky/fixed 定位、动画、图表和来源。原生 details 在各浏览器的打印行为有差异；starter 同时提供默认 open、打印 CSS 和 beforeprint/afterprint 展开恢复，仍需在目标浏览器实测。长表不宜整表 `break-inside:avoid`；允许分页、重复 thead、单元格换行。图表尽量防止跨页，但超高图应拆分，不能依靠 avoid 强挤一页。打印模式不要只显示当前章节。

单文件离线检查 `src/href/srcset`、CSS `url/@import`、运行时请求和远程字体；外部来源链接可以保留，它们不是运行依赖。多文件交付确认相对路径在交付目录有效；不打包绝对机器路径、凭据或不必要的内部原文。

## 最小检查与如实报告

1. 校对核心结论的证据链、单位、期间、口径和局限；比较是否同标准、未知值是否明示。
2. `python scripts/audit_report.py report.html --single-file --json`：记录自动检查结果并修复错误。warning 按实际内容确认，不把启发式当成硬证明。
3. 在环境允许的浏览器中检查桌面与约 390px 窄屏、键盘和焦点、JS 关闭、减动、锚点、折叠，以及打印预览的全部章节/数字/来源和表格分页。不要绕过环境的 file:// 或浏览器访问限制。
4. 若实际导出 PDF，再核对页数、文字和图表是否完成、来源是否保留、是否裁切；未执行不得写“PDF 验证通过”。

没有渲染条件时交付可审查源码与计算记录，明确“静态与计算检查已执行；屏幕视觉、无 JS 浏览器实际表现与打印分页尚未验收”。阻止交付的问题包括核心证据缺失、数值比例错误、来源虚构、正文依赖脚本才能出现；一般润色不应盖过这些问题。
