# 内容与设计选择

## 从演示迁移的方法

保留受众深度、答案优先、先全景后局部、统一比较标准、证据底座、条件与风险、责任和决策门；把“页”改成“阅读任务/章节”。自阅报告需要写出连接证据与结论的句子，不能假设讲者会口头补足。复杂参数、方法和反例进入可定位的正文后段或附录，而不是演讲备注。

一条判断的可用写法：

> **证据〔示意〕**：同一假设负载下，方案甲/乙/丙的合成容量分别为 20/40/80 件/日（S1；截至日期及口径见来源）。**解释〔推断〕**：若质量和需求相同，乙能覆盖 40 件/日的目标，丙存在闲置风险。**行动〔建议〕**：先验证乙，暂不扩大承诺。**条件**：需求持续达到目标且质量达标；需求或质量变化时重评。

证据记录可用 JSON、CSV 或短表，格式按任务选择。来源记录至少保留作者/机构、标题、发布日期或数据期间、URL/文件名、页/图/表/段落、访问或截至日期。原文主张与作者推断分开；冲突来源呈现差异和原因，不静默挑选有利数值。内部输入标明“用户提供、未独立核验”，不补造公开链接；可回溯不等于公开。来源可在每张图旁简写 S1，并链接到完整记录和回跳位置。

## 模块怎样组合

starter 是一种完整自阅路径，以下组合按任务裁剪，不要求每份报告全用：

| 模块 | 适用 | 何时拆分/替换 |
|---|---|---|
| 结论总览 + 关键指标 | 快速导读、面向决策的摘要 | 超过少量独立结论时分专题；指标必须服务于问题，不堆数字墙 |
| 机制链 + 图示 | 解释输入、处理、输出、反馈或因果假设 | 分支交叉过多时先画边界与总览，再局部放大；未证实因果标“假设” |
| 同口径比较矩阵 | 方案选择、取舍、边界 | 列数造成窄屏无法阅读时分组或逐方案展开；不要缩字硬塞；未知值写未知 |
| 阶段路线 + 决策门 | 有执行建议、依赖和复评条件 | 无日期依据时用阶段，不编造时间；数量不确定时写范围/触发条件 |
| 方法与来源 | 有数据、研究或敏感假设 | 过长可分附录，但核心成立条件与决定性限制必须在正文可见 |

纯研究解读可用“判断 → 证据 → 机制 → 争议 → 可应用边界”，无需硬加执行路线；过程复盘可用“目标 → 观察 → 解释 → 反事实 → 后续验证”。

## 参考作品的设计提炼

只记录会改变本次设计的特征。可用一个简短设计卡：

- 语义色：正文/次级信息、证据、风险、行动如何区分；同时使用标签或线型，避免色盲依赖。
- 文字：标题、章节、正文、注释的相对级差；正文采用覆盖中文的字体，舒适行距和有限行长；注释不承担关键结论。
- 留白与密度：每章一个主阅读顺序；解释段、图表、比较表交替，避免所有内容都被拆成等权卡片。
- 图表：标注直接、单位靠近数字、共用尺度，预测与实测区分；必要时保留可核对的数据表。
- 交互：目录先总览再下钻；用原生链接、按钮和 details，不用可点击 div 代替键盘可达控件。

严格模板只复制用户授权的标识与资产，明确哪些布局不可变。灵感参考保留阅读逻辑，重新选择主题合适的色彩与密度。若参考有缺陷，保留设计意图并修正可读性或准确性，而非复刻错误。
