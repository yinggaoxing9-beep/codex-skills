# Tara 操作提速复盘

来源：2026-10-14 已授权 Android 实机操作、辅助脚本检查与无输入基准。脱敏记录，不保存个人资料、联系人或聊天正文。

## 观察

上一轮总耗时约 2 小时 27 分钟。没有完整分项日志，不能确定各环节的占比。

- 原生拼音脚本每个字母、选词和标点分别调用一次 adb。第一候选词多次不符合原文，产生局部删改与整段重输。
- 读取页面通常重复 dump、cat、截图与 pull；有些只查文本的步骤也生成了截图。
- 多行草稿的行首键定位不等于全文行首，局部删除曾波及另一段。Ctrl+A 后 Backspace 在此前实测能清空己方未发送草稿。
- 导航转场产生旧树，新消息使会话列表行位置变化，审批等待后手机也可能已离开原页面。核对接收方成功拦下错误会话，不能为提速去掉核验。

## 本次无输入基准

手机 USB ADB 当时可用。顺序执行三轮，每轮先运行五次独立 adb shell true，再用一次 shell 连续执行五个 true：

| 轮次 | 五次独立调用 | 一次合并调用 |
| --- | --- | --- |
| 1 | 467 ms | 97 ms |
| 2 | 442 ms | 87 ms |
| 3 | 441 ms | 87 ms |

一次合并 dump/read 为 3471 ms，当前是消息页。只输出页面标识、包名与聚焦控件类；使用唯一临时 XML 并删除。没有输入或发送消息。

这些数据反映当时主机/ADB 往返和页面导出的成本，不代表键盘输入、审批等待或整轮任务也能按相同比例提速。

## 已实施与未验证

本次任务辅助脚本已增加：
- 先整批验证参数，按拼音短句合并 shell 点按。
- 显式提供当前设备 serial；移除历史无线地址默认值。
- 用本次唯一临时文件合并 dump/read，清理文件，失败不读旧树。
- 浏览与打开会话的截图改为显式请求；看照片与确认键盘仍需截图。
- 草稿重输入口需核对接收方、聚焦、原草稿与输入法；全选删除后读回空草稿。输入后比较预期全文，脚本不发送。
- 发现页打开会话使用当前入口 bounds，进入后再次确认接收方。

通用方法见 [ADB UI 操作提速与草稿恢复](../references/adb-ui-efficiency.md)。

本次验证只包括脚本解析、无设备预演、参数拒绝、鲜活页面读取与上述基准。更新后的坐标输入、清空入口及整轮收益尚未在真实草稿实测；没有为测试给他人发送消息。中文整句输入助手未安装，拼音候选错误的根因尚未消除。下次使用仍需重新核对设备、键盘、草稿结构及授权范围。
