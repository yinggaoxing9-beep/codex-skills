# 投研工作流入口

先处理用户本轮要解决的问题。短问答直接回答；只提想法就给候选，不强制回测或生成整套文件。需要跨步骤时才维持下面的交接状态，按需加载技能，不一次读全部资源。

| 本轮需要 | 使用已有能力 | 本轮产物 |
| --- | --- | --- |
| 想法、可计算定义、事件与策略验证、因子门禁 | alpha-hypothesis-research | 候选或不可变研究版本、失败与反证 |
| 公司事实与微观经营证据 | fundamental-signal-intake | 现有事实账本，保留时点、冲突与缺口 |
| 经营变量到价值 | evidence-driven-valuation | 已有 v2 输入和校验，不补默认假设 |
| 商业质量、财报取证与同行判断 | stock-analysis | 基本面证据与估值边界 |
| 获准因子到个股/组合模型 | 项目既有 registry 与推理接口 | 按用途、期限、条件核验后的模型输出 |

可自行完成的公开查询、代码检查和范围内检验由助手完成；只询问非公开输入或确实影响目标的偏好。某技能或接口不可用时说明缺口，保持可独立完成的工作；不假装已执行。

## 交接与调用门禁

需要保存或交给后续步骤时，读取 [交接规则](references/handoff.md)。沿用已有账本、因子 ID、实验 manifest 和模型输出，在外层附加内容版本与上游引用；不另建活跃因子注册表。

任何小想法允许保留为 idea；期限或定义未定则暂不正式命名。正式名为 `Alpha_<N>Day_<semantic_slug>`，N 代表未来交易日期限，lookback 与版本另存。旧项目命名不兼容时明确阻塞，不自动小写化、重命名旧 ID 或谎称可以直接注册。

研究、影子和生产资格分开。消费时重查原生 registry 的状态、用途、期限、股票池、有效期、数据可得时点及条件；失效或未获准因子不能进入本次调用，生成器不能签发 ACTIVE。相似因子按共同信息来源和相关性处理，不能一因子一票虚增置信度。

短、中、长期分别绑定明确交易日期限、标签与验证证据，不套统一窗口。不用 LLM 主观投票、排名或截面分数生成涨跌概率。缺模型、校准证据、输入或适用性时，概率为 unknown/null，说明原因；unknown 不等于 0。只有已验证组合模型及同版本、同期限、同标签、同因子集合、同适用范围的校准/可靠性证据齐全时才引用概率，说明上涨/下跌/中性阈值；仅互斥完备的标签要求和为 1。经过样本外可靠性验证的原始概率可以保留，不强制另套校准器；删去失效因子或变更组合后不能沿用旧校准。

调用前核对当前授权范围。研究与回测不授权调度、持续外部调用、通知、交易或生产激活；设计状态保持 enabled=false，直到另有明确启动授权。历史案例也不继承授权。

## 面向用户的结果

围绕发生了什么、支持与反证、数据时点、可信或未知及原因、接下来能做什么组织结果。展示已核实的计算和证据，保留失败轨迹。分清软件检查、历史研究、影子表现与生产资格；模型概率不构成盈利保证。

接入量化工程仓库时才读 [已核验接口与缺口](example/quant-engineering.md)，先重新核验现场。
